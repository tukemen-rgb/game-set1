# 使用感と材質の更新 — 2026-09-17

1990年代の大阪・千里中央を舞台に、住民が使い続けているベランダとして、乾いた汚れと材質の違いを作り込みました。素材名は既存モデルの指定に従い、汚れの程度・施工時の製品・経過年数は制作上の仮定です。実在の建物の劣化状態を測定したものではありません。

## 部品と表面

| 対象 | 素材・表面 | 今回の使用感 | 汚れの根拠 |
|---|---|---|---|
| 防水床 | 灰緑の塗膜、細かな滑り止め状の凹凸 | 壁際・手すり下の砂埃、排水口周囲の薄い乾燥堆積 | 実際の床端、返し手すりの台座、排水フランジの位置 |
| 手すり下の立ち上がり | コンクリート、微細な色差と小さな表面の穴 | 台座付近の粉塵、一箇所の薄い錆汁跡 | 実際の塗装鋼製台座の角に設けた小さな塗膜損傷 |
| 正面・返し手すり | 濃色の塗装鋼、細かな塗膜起伏 | 上向き面の埃、手を触れる部分の艶の差、正面5台座中1箇所の小さな錆 | 向き、手すり上端、選択した台座の座標 |
| 外壁 | 既存の塗装繊維セメント板 | 換気口下と配管固定具下の細い雨だれ、床近くの埃 | 実在する換気口2隅・配管クランプ3箇所・床との境界 |

錆や粉塵は金属として光らせず、非金属の付着物として色・粗さ・微細な凹凸を変えています。アルミ窓枠とステンレス排水蓋に鋼材の錆処理を流用していません。乾燥した夏の日の設定を保ち、水たまり・濡れた光沢・漏水の演出は追加していません。

全景で主張し過ぎず、寄ると違いが分かる程度に調整しています。初回のぼやけた雨だれは、細い流れ跡と薄い周辺堆積に分けて修正しました。汚れのための照明や影の描き込みはありません。

## モデルへの適用方法

`build_balcony_drainage_integration.py` の既存床ownerに任意の汚れ処理を追加し、`refine_window_service_facade_surface.py` の既存外壁材を拡張しました。`balcony_context_materials.py` は共有の材質処理、`refine_balcony_context_weathering.py` は供給されたシーンに適用する処理です。新しい床・外壁・手すりの形状ownerは作成していません。

排水穴、床勾配、天井点検口、台座と手すりの接合、窓・換気口・配管の開口は形状を維持します。変更対象は防水床1メッシュ、コンクリート1メッシュ、塗装鋼2メッシュ、既存の壁パネルです。それ以外は同じ入力シーンから引き継ぎます。

床・コンクリート・鋼製手すりには、面ごとの実寸に基づく材質座標を割り当てます。排水穴の内壁と床の外周側面を同じ投影に混ぜないように分割しました。小さな面取り部分の投影誤差は4 mm以下に制限し、実行記録に計測値を残します。三角形の位置・向き・数と各頂点の法線は維持しています。

色、金属度／粗さ、法線の各画像をGLBに格納します。色はsRGB、粗さ・金属度・法線は線形値として扱い、GLBの色係数は白に統一しています。格納規約は [Khronos glTF 2.0仕様](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#materials) に従います。OBJ/MTLは形状と基本色の互換用で、PBRの完全な再現はGLBを使ってください。

## 検証と確認画像

実行結果は `context_weathering_2026-09-17.execution.json`、成果物内では `verification.json` を参照してください。

- 書き出し・再読み込み後まで、全ノードの配置、全三角形、対象外の形状・法線・UV・材質を照合。
- 変更対象の法線、UV、格納された材質画像も再読み込み後に照合。
- 床中央の検査点、雨だれ起点より上、損傷を加えない他の正面台座に、新しい汚れ・錆が出ないことを確認。
- 全景、排水口、台座、換気口、別方向の光、変更前の床を実メッシュで描画。照明差の画像で同じ材質がどう見えるか確認。

画像は全三角形を渡した材質色付きの外部CPUプレビューです。画角のために部品を削除したり、画像生成で描き足したりしていません。元の室外機や換気口など、今回対象外の部品には既存の材質座標・描画上の残件があります。これらを汚れで隠していません。

## 再実行

依存関係は既存の `UnityProject/Tools/requirements-balcony-repair.txt`。実行環境のバージョンは実行記録に含めます。

```bash
python UnityProject/Tools/refine_balcony_context_weathering.py \
  --input-root /path/to/previous-surface-models \
  --input-pattern 'BalconyExteriorHeroDrainedStructuralRepairFacadeRefined3600_{level}_SurfaceRefined.glb' \
  --output /path/to/new-weathering-output --render
```

出力先は新規フォルダを指定します。`--input-pattern` は供給する全体モデルの名前に変更できます。基準となる `LOD0` とMASTER/LOD1/LOD2/LOD3を供給します。汚れの評価はシーン内の固定点を基にした制作上の近似であり、流体・腐食の物理シミュレーションではありません。
