# ChatGPT など画像生成AIの使いどころ（API キー不要ルート）

このプロジェクトで画像生成AIが**効く所と効かない所**、そして手作業で
ChatGPT に投げる場合の具体手順とプロンプト。

## 効く / 効かない

| 用途 | 効果 | 補足 |
| --- | --- | --- |
| **プリレンダー背景（本命）** | ◎ | 固定カメラ4つ＝**4枚だけ**で全画面が写真級になる |
| 空・遠景のパノラマ（skybox） | ◎ | 1枚で空と遠景の情報量が跳ね上がる。前後関係の問題が無く低リスク |
| タイトル画面・キーアート・UI | ◎ | そのまま使える |
| 見た目のすり合わせ（コンセプトアート） | ○ | 実装前に方向性を決める用途 |
| タイル用テクスチャ | △ | 継ぎ目（シームレス）が苦手。要後処理（ミラー＋ブレンド） |
| 3Dモデル（GLB） | × | 画像は3Dにならない。image-to-3D は別サービス（Tripo3D 等・API必要） |

## 本命の手順: img2img で「透視が合った」背景を作る

ゼロから生成した絵を背景に貼ると、3Dのキャラと**透視がズレて浮く**。
そこで **ゲームのレンダーを下絵として渡し、構図を保ったまま質感だけ写実化**する。
本家「ぼくのなつやすみ」も背景は3Dシーンからのレンダー由来で、同じ考え方。

1. `docs/plates/ref_*.png` の4枚（`test/CamShots.cs` が生成）を ChatGPT にアップロード
2. 下のプロンプトで「構図・カメラ位置・建物の輪郭を厳守」して写実化させる
3. 返ってきた画像を `assets/plates/` に置く
4. 背景板として貼り、3Dジオメトリは**深度と当たり判定だけ**の不可視に切り替える
   （キャラが建物の陰に隠れる前後関係を保つため）

### そのまま貼れるプロンプト（img2img・1枚目）

> この3Dラフを、**構図・カメラアングル・建物や樹木の位置と輪郭を一切変えずに**、
> 写真のようにリアルな一枚絵にしてください。
> 舞台は2000年ごろの日本のニュータウン、夏の朝。5階建ての板状団地、
> ベランダの手すり、外壁の雨だれ、屋上の給水塔、街路樹、電線。
> 実写風・自然光・人物は入れない・文字や看板の文字は入れない。
> アスペクト比は元画像と同じ16:9。

### 2枚目以降（統一感を保つ）

> さっき作った画像と**同じ町・同じ画風・同じ時間帯・同じ光**で、
> 今度はこの3Dラフ（別アングル）を同じように写実化してください。

前の生成結果も一緒に添付して「これと同じ世界」と伝えるのがコツ。
4枚がバラバラの町に見えると台無しになる。

## 注意点

- **実在の団地の写真そのものを生成元に使わない**。「2000年ごろの日本の
  ニュータウン」という一般的な指定に留める（実在建築物・写真の権利対策）
- 生成物の権利は各サービスの規約による。OpenAI は規約上、出力の権利を
  利用者に帰属させているが、**利用時点の最新規約を必ず確認する**
- 文字・看板の文字は破綻しやすいので「文字を入れない」と指定し、
  必要な看板は後からゲーム側で重ねる
- 人物を入れない（キャラは3Dで動くため。背景に焼き付くと動かない）

## API 経由との違い

| | ChatGPT（手動） | API（GOOGLE_API_KEY 等） |
| --- | --- | --- |
| コスト | 既存サブスクの範囲 | 従量課金（画像1枚 数円〜十数円） |
| 反復 | 人が目で見て選べる | スクリプトで自動反復（Godogen の asset-gen が使える） |
| 向く用途 | 背景4枚など**少数・高品質** | テクスチャ多数・アニメーション連番 |

少数精鋭の背景プレートなら **ChatGPT 手動で十分**。
