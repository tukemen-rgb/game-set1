# 画像の受け渡しをどう自動化するか

「AI が生成した画像を、どうやって GitHub に入れるか」の選択肢と評価。
テキストは AI が直接コミットできるが、**バイナリだけが渡せない**——
この一点をどう埋めるかの問題。

## 結論（先に）

**まず1枚を手動で通して検証する。自動化はその後。**

理由: img2img が本当に下絵の遠近を保つのか、それを Godot に貼って
3Dキャラと合うのかは、**まだ1枚も確かめていない**。ここが崩れると
113枚すべてが無駄になる。1枚の検証コストは数分、失敗したときの
手戻りは113枚。順番を逆にしてはいけない。

検証が通ってから、下の C（APIキー）で一気に自動化するのが最短。

## A. URLS.txt 方式（実装済み・要検証）

AI が `incoming/URLS.txt` に「ID = 公開URL」を書くだけ。取り込み側が
5分ごとに自動でダウンロードする。**人手ゼロ。**

```
TEX-wall_danchi = https://example.com/foo.jpg
BG-danchi-noon  = https://example.com/bar.png
```

- 実装済み・動作確認済み（実URLからのDL成功、404と非画像は自動で破棄）
- ID を左に置く規則（URL 側に `=` が入りうるため）
- 適用後 URLS.txt は自動削除される
- **懸念**: ChatGPT のチャット内に表示される画像URLは認証付きの短命URLで、
  外部から取得できない可能性が高い。**1件書いてもらえば5分で判明する。**
  取得できなければ自動で失敗ログが出るだけなので、試すコストはゼロ

なお「GitHub Actions で回収する」案も、結局**どこから取るか**という
同じ問題に行き着く。Actions を挟んでも公開URLが要る点は変わらない。

## B. MAP.txt ＋ ドラッグ＆ドロップ（実装済み・確実）

社長が画像を落として GitHub にドラッグ、AI は対応表テキストだけ書く。

- **確実に動く。リネーム不要。**
- 社長の作業は1バッチ（3〜5枚）あたり約1分
- 113枚 ≒ 23バッチ ≒ **合計25〜30分**の手作業
- 検証フェーズはこれで十分

## C. 画像生成API（本命の自動化）

APIキーをもらい、取り込み側が直接画像を生成する。**人手ゼロ、
しかも生成→目視QA→プロンプト修正→再生成のループまで自動化できる。**
Godogen の `asset-gen` スキルがこの用途のツールを持っている。

参考価格（Godogen の asset-gen skill に記載の単価）:

| モデル | 1枚あたり | 113枚の概算 |
| --- | --- | --- |
| Gemini 1K | 7¢ | 約 8 ドル |
| Gemini 2K | 10¢ | 約 11 ドル |
| Grok | 2¢ | 約 2.3 ドル |

img2img（下絵を渡す）は Gemini が指示追従に優れるため、`BG-*` は
Gemini、テクスチャ類は Grok、という使い分けが妥当。
**必要なのは `GOOGLE_API_KEY`（と任意で `XAI_API_KEY`）だけ。**

手作業30分 vs 千数百円。枚数が増えるほど C が有利になる。

## 進め方の推奨

1. **BG-danchi-morning を1枚、B の手順で入れる**（今すぐできる）
2. 取り込み側で Godot に貼り、**遠近が合うか検証**してプロンプトを調整
3. 同時に A を1件試す（コストゼロ・5分で判明）
4. 検証が通ったら C に切り替えて残りを一気に生成
