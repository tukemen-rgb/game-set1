# 8月1日〜31日 自動走破の監査

検査: `test/Month.cs`（新規・1本）。8/1 から結末まで一気に走らせ、`DEBUG_MSG=1`
の標準出力ログを `docs/audit/month.log` に保存して読んだ。コミットはしていない。

## 対象と方法

- HEAD `b37b6d0` に **未コミットの作業ツリー変更**（`scripts/SummerMain.cs`）が
  乗った状態。監査中も別の作業で `SummerMain.cs` が更新され続けたので、
  ログごとにビルド時の `SummerMain.cs` の md5 を記す。
  - `month.log`（本走・31日＋結末）: `fe0a6e6b…`（16:28 UTC）
  - `month-e36cc549.log`（本走・1つ前の版）: `e36cc549…`（16:23 UTC）。この版で
    見つけ、直後の版で直っていたものは「監査中に直った」として末尾に記す
  - `month-noradio.log` / `month-onlyshop.log` / `month-buy.log` / `month-fast.log`:
    `ffea6f88…`　`month-quickz.log`: `fe0a6e6b…`　`month-shelfhold.log`: `b879c1e6…`
- 実行（headless で 31日 ≒ 22 秒。xvfb でも同じ結果が出ることは 1 日ぶんで確認）:
  ```
  export DOTNET_ROOT=/opt/dotnet PATH="$PATH:/opt/dotnet"; dotnet build -v q --nologo
  DEBUG_MSG=1 DEBUG_SPAWN=1 godot --headless --path . --fixed-fps 30 --quit-after 29500 \
    --script res://test/Month.cs 2>&1 | grep -E "^\[msg|^\[spawn|^\[day|^\[label|^\[diary|^\[dex"
  ```
- 1日の動線（瞬間移動）: 8時台にラジオ体操の台で決定 → となりの おばさん →
  おばさん → あさがお → 自販機の前で決定 → 駄菓子屋で決定2回（一言→品書き）→
  Z で閉じる → 広場 → チャイムの後に ベンチの おじいさん。
- **時間の圧縮は 1時間=2.0秒（1日 22秒）にした。** 指示の 0.35秒/時（1日 4秒）で
  試したところ、`ShowMessage` の「前の文から 1.2 秒未満なら待ち行列（2つまで）、
  あふれたら即上書き」という仕組みに検査の押し方そのものが引っかかり、上書き警告
  と取りこぼしが検査の産物になった（`month-fast.log`: 8/1 に押したはんこの文が
  一度も出ず、朝の文が 0.13 秒で上書きされる等）。2.0秒/時なら 8:00 / 10:00 /
  11:00 / 13:00 / 15:00 / 16:00 / 17:00 の合図の間に、合図から 1.2 秒以上あけて
  押せる。
- Month.cs の追加ログ: `[day]`（日付ラベルが変わった瞬間）、`[label]`（画面の文が
  変わった。品書きと結末は ShowMessage を通らないのでこれで拾う）、`[diary]`
  （絵日記の本文。DiaryText も ShowMessage を通らない）、`[dex]`（品書きの Z で
  ずかんが開いた）。環境変数 `MONTH_START`（開始日）、`MONTH_SPH`（秒/時）、
  `MONTH_QUICKZ` / `MONTH_BUY` / `MONTH_NORADIO` / `MONTH_ONLYSHOP` /
  `MONTH_SHELFHOLD` で動線を変えられる（各欠陥の再現用）。

## 欠陥

### 中

**A. となりの おばさんが 8/8 以降も「ラジオたいそう、行った？ はんこ もらえるうちに 行きなさい」**
- 証拠: `month.log` 639行（8/11）・947行（8/16）・1220行（8/21）・1532行（8/26）・
  1828行（8/31）。ラジオ体操は 8/7 で終わり（`RadioLastDay = 7`）、のぼりも
  8/8 から消える（`_radioBanners.Visible = _day <= RadioLastDay`）。
- 原因: `CheckFolk` が `lines[(_day - 1 + idx * 2) % lines.Length]` で日付だけから
  台詞を選ぶ（`SummerMain.cs` 2379行付近）。となりの おばさんの5番目の台詞は
  8/1・6・11・16・21・26・31 に出る。
- 直し方: 期間限定の台詞に条件を持たせる（例: `Townsfolk` の台詞を
  `(string Text, System.Func<int,bool> When)` にして、この行は `day <= RadioLastDay`、
  外れた日は次の候補へずらす）。8/8 以降は「ラジオたいそう、おわっちゃったわね」
  のような言い換えにすると、期間の記憶が町の側にも残る。

**B. おばさんが「なつまつりの 提灯、もう ついてたわ」と 8/3 から言う**
- 証拠: `month.log` 156行（8/3）・472行（8/8）・771行（8/13）・1064行（8/18）・
  1354行（8/23）・1640行（8/28）。屋台と提灯は 8/24 しか見えない
  （`_festivalNode.Visible = _day == FestivalDay`、1790行付近）。8/24 当日は
  この台詞にならない。
- 原因: A と同じ（日付だけの周期選択）。
- 直し方: この行を `day >= FestivalDay - 1 && day <= FestivalDay` に限定するか、
  提灯を前日から掛けて台詞と絵を合わせる。

**C. 8/31 におばあさんが「なつまつり、いくのかい。うちも 屋台を 出すよ」**
- 証拠: `month.log` 1850行。祭りは 8/24 で、8/23 にも同じ台詞（`GrannyLines[6]`
  は 8/7・15・23・31 の順番だが、8/7・15 は雨の前日の文に取られる）。
- 原因: `GrannyLine` の `GrannyLines[(_day - 1) % 8]`（2585行）。祭りの前後の
  区別がない。ついでに祭り当日 8/24 は「おや、また 来たね」で、店先で祭りに
  触れない（1429行）。
- 直し方: `_day > FestivalDay` なら 6 番を飛ばす（または「まつり、たのしかった
  かい」に差し替え）。8/24 は祭り専用の一言を先に返す。

**D. 朝のひとことが天気と食い違う**
- 証拠: 8/27（雨）に「せんたくものが、もう ほされて いる。」（`month.log` 1587行、
  `[day] 8月27日(日) 08:01 雨` は 1589行）。8/12（晴れ、翌日も晴れ）に
  「きょうも 天気が いい……と 思ったが、そうでも ない かも。」（694行）。
  雨の朝（8/8・19・27）は雨に触れる文が一つもない（467・1111・1587行）。
- 原因: `MorningLine` の 6 行が `(_day - 1) % 6` の周期だけで選ばれ、
  `WeatherOfDay` を見ない（2485〜2495行）。
- 直し方: 雨の日は先に「あめ。まどが くもって いる。」等の雨の文を返し、
  「そうでも ない かも」は翌日が雨／くもりの日だけに限定する。

**E. 8/7 の日記が、はんこを押していなくても「はんこが そろった」**
- 証拠: `month-noradio.log` 30行（8/7 を はんこなしで走らせた: 「ラジオたいそうの
  さいごの日。はんこが そろった。」）。朝の文のほうは押した数で言い分ける
  修正が入っている（`month.log` 402行「はんこは 6こ たまった」）のに、日記は
  据え置き。
- 原因: `DiaryText` が `Events[_day].Diary` を無条件に返す（2727〜2728行）。
  `Events[7].Diary` は固定文。
- 直し方: 8/7 は `_stamps` で分ける（`_stamps >= RadioLastDay` → そろった、
  それ以外 → 「はんこは N こ だった」）。朝の文と同じ分岐を関数にして両方から使う。

### 軽微

**F. 五時のチャイムと「ヒグラシが 鳴きはじめた」が同じフレームに出る**
- 証拠: `month-e36cc549.log` に 31 日中 27 日「上書き（0.00秒）: 「五時の チャイムが
  鳴った。」→「ヒグラシが 鳴きはじめた。」」（64・134・203行…）。最新版の本走では
  ヒグラシが待ち行列に入って 3 秒後に出るので警告は消えたが、待ち行列が満杯なら
  同じ上書きになる（`month-shelfhold.log` では ヒグラシが「待ち2」で最後まで出ない）。
- 原因: `ChimeHour = 17.0` と `SlotEdges` の `17.0` が同じ時刻（1529行、648行）。
  `CheckChime` → `RefreshCicadas` の順で同一フレームに 2 回 `ShowMessage`。
- 直し方: ヒグラシの区切りを 17.1 にずらす、またはチャイムの文に
  「……ヒグラシが 鳴きはじめた。」を足して 1 文にする。

**G. 16:00 の「セミの こえが かわった。」は顔ぶれが変わっていない**
- 証拠: 晴れ・くもりの全日で 15:00「ツクツクボウシが 鳴きはじめた。」の直後に
  16:00「セミの こえが かわった。」（`month.log` 56行ほか）。15:00 と 16:00 の間に
  出入りする種はない（ツクツクボウシ 15〜19、アブラ・ミンミン 10〜17）。
- 原因: `PhaseOfHour` の境（11/16時）で `RespawnCicadas` が総入れ替えし、
  `ChangeLine` が null のときの既定文が「かわった」（560〜562行）。
- 直し方: `_changeLine == null` なら文を出さない（`RefreshCicadas` と同じ扱い）。
  総入れ替えで個体が消えるのが気になるなら、境でも `RefreshCicadas` にする。

**H. 品書きを開いたままでも時間が進み、チャイムが品書きを消す**
- 証拠: `month-shelfhold.log`（品書きを 15:30 に開いて放置）: 16:00 の合図は
  「待ち1」に回ったが、17:00 の「五時の チャイムが 鳴った。」は品書きの上に直接
  出た（`_shopOpen` のまま。矢印を押せば品書きが戻る）。
- 原因: `CheckShop` は `_shopOpen` 中も `_hour` を止めない。`ShowShelf` は
  `immediate` で、その後 1.2 秒経てば他の文が直接上書きできる。
- 直し方: ずかんと同じく `_shopOpen` 中は時間を止める（`_Process` の先頭で
  `CheckDex` と同様に早期 return）。少なくとも `_shopOpen` 中の `ShowMessage`
  は待ち行列へ回す。

**I. 8/16 は雨なのに送り火が焚かれる**
- 証拠: `month.log` 946行 `[day] 8月16日(水) 08:01 雨`。`UpdateOkuribi` は
  `_day == OkuribiDay && _hour >= 17.0` だけで、天気を見ない（624行付近）。
  雨の日は `_rainFx` が降り続ける。
- 直し方: 雨の日は炎を小さく（軒下）にするか、朝の文を「雨の おくりび」に
  変えて絵と言葉を合わせる。日付固定なので毎周同じ矛盾になる。

**J. 待ち行列が満杯のときは 0.4 秒未満でも即上書き（仕組みの限界）**
- 証拠: `month.log` の `[msg!]` 4 件はすべて「待ち2」（38・365・533・1784行）。
  自販機の文の 0.4 秒後に 13:00 の合図が来て、行列が満杯だったので上書きされた
  （13:00 の 0.4 秒前に押した検査の動線が原因で、遊びで起きる確率は低い）。
- 原因: `ShowMessage` の `_msgQueue.Count < 2` を外れると即上書き（1327行付近）。
  逆に行列に入った文は、次の文が 1.2 秒以上あけて直接出続けるかぎり出番が来ず、
  最新版では日の終わりに捨てられる（8/16 の「十円。もらって おこう。」: 960行の
  `[msg~] 待ち2` のあと一度も出ない）。
- 直し方: 満杯なら行列の一番古い文を捨てる（表示中の文は守る）。行列の文には
  入れた時刻が付いた（`At`）ので、一定時間（例: 8 秒）を過ぎた文は出さずに捨て、
  「拾った」「捕まえた」のような行動の結果は `immediate` にして必ず見せる。

**K. お盆の朝の文「どこの まども、いつもより あかるい」が朝 8 時に出る**
- 証拠: `month.log` 756行（08:01）。窓が点くのは 17:12 以降（`UpdateWindows` の
  `(_hour - 17.2) / 1.6`、1713行）で、お盆の差（10 室中 7 室）は夕方にしか見えない。
- 直し方: 「きょうは おぼん。夕方、まどが いつもより あかるく なるらしい。」の
  ように未来形にする。

**L. 8/7 の朝「はんこは 6こ たまった」と、その日のはんこ**
- 証拠: `month.log` 402行（朝「6こ たまった」）→ 405行（同じ朝に 7/7 を押す）→
  462行（日記「そろった」）。皆勤の人は最終日の朝に「6こ」と言われる。
- 原因: `EndDay` 末尾の `_stamps >= RadioLastDay - 1` 分岐（今日のぶんを含めない）。
- 直し方: 「きょう おせば ぜんぶ そろう」に言い換える（数を言わない）。
