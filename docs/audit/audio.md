## 2. 【重大】ループが 0.81 秒で回っている

**何が**: セミ3種と雨の 4.0 秒ループが、実際には**先頭 0.81 秒だけ**を繰り返している。
ミンミンゼミの「ミーン…ミンミンミン」（2秒周期で設計）は「ミーン」の途中で切れて
頭に戻り、ヒグラシの 9 音下降は 5 音目で戻り、雨の大粒 220 個のうち先頭 0.81 秒に
入る約 45 個だけが 0.81 秒周期で機関銃のように繰り返す。

**証拠**:
1. `assets/audio/*.wav.import` は全て `compress/mode=2`（= Quite OK Audio、非可逆圧縮）。
   Godot 4.4 の新規インポート既定値もこれで、scratch プロジェクトで確認した
   （`compress/mode=2` が自動生成される）。
2. GDScript で読み込んだ実体（`godot --headless --script probe.gd`）:
   ```
   cicada_morning format=QOA data=35720 bytes mix_rate=22050 length=4.000s
   cicada_day     format=QOA data=35720 bytes ...
   cicada_evening format=QOA data=35720 bytes ...
   rain           format=QOA data=35720 bytes ...
   ```
   `Data.Length / 2 = 17860` フレーム = **0.810 秒**（PCM16 なら 176400/2 = 88200 = 4.0 秒）。
3. 録音の包絡（10ms RMS）の自己相関にループ周期が出る:
   - `screenshots/rainaudio`（雨の日 11 秒）: 遅れ **0.81s = 0.93**, 1.62s = 0.85, 2.43s = 0.78, 3.24s = 0.70 … 4.0s = **-0.04**
   - `screenshots/audio`（晴れ 24 秒）: 0.81s = 0.56, 1.62s = 0.43, 2.43s = 0.35, 4.0s = -0.06
   - `screenshots/run`（18 秒）: 0.81s = 0.49, 1.62s = 0.33, 4.0s = -0.03
   4.0 秒周期は一切見えず、0.81 秒（= 17860/22050）の整数倍だけが立つ。
4. 0.81 秒地点はループ用に閉じていないので、そこで波形が跳ぶ:
   サンプル 17859→0 の跳びは morning -0.244（隣接サンプル差 RMS の **1.37 倍**）、
   rain -0.108（0.53 倍）。ファイル末尾→先頭（本来の継ぎ目）は 0.11〜0.27 倍で小さい。

**原因**（コードから確定）: `scripts/SummerMain.cs`
- 916 行: `stream.LoopEnd = stream.Data.Length / 2; // 16bit モノラル`
- 947 行: `rainStream.LoopEnd = rainStream.Data.Length / 2;`

`Data` は QOA の圧縮バイト列（1 サンプルあたり約 3.2bit）なので、/2 は
サンプル数にならない。コメントの「16bit モノラル」という前提が、インポート既定値
（QOA）と食い違っている。

**直し方**（どれか一つ。A が最小）:
- **A. コードで正しい終端を出す**: 916 行と 947 行を
  `stream.LoopEnd = Mathf.RoundToInt((float)(stream.GetLength() * stream.MixRate));`
  に置き換える（`GetLength()` は QOA でも 4.000 を返すことを上の probe で確認。
  結果は 88200）。913 行のコメント「16bit モノラル」も直す。
- **B. インポート側でループを閉じる**: `cicada_morning/day/evening.wav.import` と
  `rain.wav.import` の `edit/loop_mode=0` → `1`（Forward、`loop_end=-1` は末尾を意味する）
  にして、914〜916 行と 945〜947 行を削除する。コードの「インポート設定に頼らず」
  という方針とは逆になる。
- **C. 圧縮をやめる**: 4 本の `.import` で `compress/mode=2` → `0`（PCM）にすると
  `Data.Length/2` が正しくなる（1 本 176KB、非可逆圧縮のざらつきも消える）。
  ただし「なぜ /2 で良いか」がインポート設定に依存するままなので A と併用が望ましい。

直すとセミの床の音量は 1dB 以内で動く（先頭 0.81 秒の RMS: morning -16.4 / day -15.0 /
evening -14.2 dB、全体 -16.5 / -15.8 / -15.3 dB）。evening が約 1dB 静かになる程度。

## 3. 【中①】4.0 秒の継ぎ目に 8〜10dB・約 15ms の谷

**何が**: 重大①を直して 4.0 秒で回るようになると、継ぎ目ごと（4 秒に 1 回）に
短い谷ができる。今は 0.81 秒地点で切れているので表に出ていないが、
ループ先頭の谷は 0.81 秒ごとに鳴っている（下の数値）。

**証拠**（5ms 窓 RMS、ファイル解析）:

| ファイル | 先頭 0〜5ms | 5〜10ms | 10〜15ms | 末尾 -10〜-5ms | 末尾 -5〜0ms | 中央 1 秒 |
|---|---|---|---|---|---|---|
| cicada_morning | **-26.0** | -18.4 | -15.2 | -19.3 | **-25.4** | -16.4 |
| cicada_day | **-25.2** | -17.8 | -19.1 | -18.2 | **-23.9** | -15.9 |
| cicada_evening | -19.6 | -11.7 | -10.3 | -25.2 | -28.8 | -15.7 |
| rain | -18.0 | -18.9 | -19.0 | -15.1 | -17.0 | -17.4 |

morning / day は継ぎ目の前後 5ms が中央より 8〜10dB 低い（evening は
「カナカナ」が 0 秒から始まる設計なので先頭が大きく、末尾が小さいのは意図どおり。
rain は谷なし）。継ぎ目のサンプル跳び自体は小さく（末尾→先頭 -0.021〜-0.046、
隣接差 RMS の 0.11〜0.27 倍）、クリック（プツッ）にはならない。DC も
先頭 100ms が -0.011〜-0.023、末尾 +0.0004〜+0.0009 で、100ms かけて動くので可聴ではない。

**原因**（コードから確定）: `tools/gen_audio.py` の `add_tone()` 51〜52 行
```python
edge = min(1.0, t / 0.01, (dur - t) / 0.01)
env *= max(0.0, edge)
```
連続音（`dur=DUR` で 4 秒鳴りっぱなしのニイニイゼミ・アブラゼミ・夕方の虫）にも
両端 10ms のフェードがかかるため、ループ先頭と末尾でその分だけ音が痩せる。
フェードを外すだけだと、`detune` でずらした周波数が 4 秒で整数周期にならず
（例 4200×1.013×4 = 17018.4 周期）継ぎ目で位相が跳んでクリックになる。

**直し方**: `add_tone()` に「4 秒鳴りっぱなしの音はループで閉じる」分岐を足す。
```python
f = freq * detune
if dur >= DUR:                       # 連続音: 周波数を 1/DUR Hz 刻みに丸めて継ぎ目で位相が合うようにし、端のフェードは掛けない
    f = round(f * DUR) / DUR
...
edge = 1.0 if dur >= DUR else min(1.0, t / 0.01, (dur - t) / 0.01)
```
（`v` の 2 行で `freq * detune` を `f` に置き換える。2 倍音 `2f` も自動的に閉じる。）
連続音の変調周波数 28 / 44 / 33 Hz はどれも ×4 で整数なので変調は既に閉じている。
直した後は「先頭 5ms ≈ 中央」になるはず（5ms 窓で差 2dB 以内が目安）。

## 4. 【中②】虫あみの「ヒュッ」（sfx_swing）が床から +4〜6dB しか出ない

**何が**: 振った瞬間の音が、セミの床にほぼ埋もれている。

**証拠**: `CLOSEUP_SWING=1` で 240 フレーム撮影（`screenshots/audit_swing`、
朝 8 時・晴れ・cicada_morning が床）。20ms 窓 RMS の包絡、床の中央値 -25.3dBFS。
振りは 1.2 秒おき（フレーム 37 の倍数）。

| 振り | 山の時刻 | 山 (dBFS) | 直前 0.3 秒の床 | 差 |
|---|---|---|---|---|
| 1 | 1.30s | -13.0 | -25.4 | +12.4 （**セミを捕った音が重なっている**: 880/1320Hz の Goertzel が -24/-18dB で、床区間より 50dB 高い） |
| 2 | 2.56s | -19.2 | -25.7 | +6.4 |
| 3 | 3.74s | -19.8 | -25.2 | +5.4 |
| 4 | 4.92s | -19.6 | -25.0 | +5.4 |
| 5 | 6.14s | -20.1 | -24.3 | +4.2 |
| 6 | 7.36s | -19.6 | -23.5 | +3.9 |

釣りの「ツン」（当たり時にも sfx_swing が鳴る、`screenshots/audit_fishing` 11.50s）
も 50ms 窓で -15.5dB だが、直後 11.60s の捕獲音（-13.8）と連続していて単独では
評価できない。

比較: 足音は +5.1〜+8.6dB（下記）、捕獲音は +12〜13dB、チャイムは +7〜11dB。
振る音は一発ものの中で**最も小さい**。しかも「ヒュッ」は広帯域ノイズで、
セミの床（同じくノイズ状・3〜5kHz）と帯域が重なるため、同じ dB でも目立たない。

**原因**: `scripts/SummerMain.cs` 962 行 `_sfxSwing = MakeSfx("sfx_swing", -10f);`。
ファイル自体の 50ms 最大 RMS は -10.9dBFS で他の効果音と同程度（catch -8.9 /
escape -11.2 / step -13.1）だが、ゲイン -10dB は効果音の中で一番深い
（firework -4 / catch -6 / step -7 / escape -8 / swing -10）。

**直し方**: 962 行を `MakeSfx("sfx_swing", -5f)` にする（+5dB）。
ファイルの 50ms 最大 -10.9dB + (-5) = -15.9dBFS で、床 -25.3 から約 +9dB。
捕獲音（-14.9）とチャイムに並ぶ高さで、足音（-18〜-20）より上に出る。
もし 5 秒に 1 回の連打で耳につくようなら -6f。

## 5. 【中③】逃げられた音（sfx_escape）が足音と同じ高さ

**何が**: 「にげられた」の音は鳴っているが、走っている足音と同じ高さで、
足音の列の中に紛れる。

**証拠**: `screenshots/startle/frame.wav`（走って驚かせる検査、4.67 秒、
床の中央値 -25.2dBFS）。3.62〜3.90s に 250〜300Hz のエネルギーが -38 / -34dB
（セミだけの 2.9〜3.1s は -89 / -76dB）。sfx_escape は 200→360Hz のスイープに
62Hz の振幅変調なので、この帯域の跳ね上がりが逃げ音の証拠。
その区間の 50ms 窓 RMS の山は 3.65s -18.8 / 3.80s **-18.5**dB（床から +6.5〜7dB）。
同じ録音の足音（走り）の山は -17.6〜-19.8dB で、区別がつかない高さ。
今回の 2 本の撮影（swing 240f / fishing 420f）では捕獲が続いて逃げ音は 1 度も
鳴らなかった（fishing の唯一の当たりも捕獲: 880/1320Hz が -24/-18dB）。

**原因**: `scripts/SummerMain.cs` 964 行 `_sfxEscape = MakeSfx("sfx_escape", -8f);`。
ファイルの 50ms 最大 -11.2 + (-8) = **-19.2dBFS** で、足音（-13.1 + (-7) = -20.1）と 1dB 差。

**直し方**: 964 行を `MakeSfx("sfx_escape", -5f)`（-16.2dBFS、床から約 +9dB、
振る音の提案値と同じ高さ）。「振る → 逃げた」の 2 音が同じ高さで並ぶので
物語として揃う。捕獲音（-14.9）より小さいままなので、成功と失敗の差も残る。

## 8. 【軽微】

### ① sfx_firework.wav の後半 44% が無音
- 証拠: 無音率 43.9%。`sfx_firework()` は胴鳴りを `t < 0.9` で止め、火の粉は
  `rng.uniform(0.18, 0.85)` + 20ms までなので、0.87〜1.60s に何も書かれない。
- 影響: 音には出ない（-4dB でも無音は無音）。ファイルが 0.7 秒分大きいだけ。
  `Finished` シグナルで次の処理を待つコードは無い（grep 済み）ので遅れも出ない。
- 直し方: `tools/gen_audio.py` 末尾 `save_oneshot("sfx_firework", sfx_firework, 1.6)`
  の `1.6` → `0.95`。

### ② 花火の標本ピークがクリップまで 2.5dB
- 証拠: `screenshots/festival/frame.wav` の標本ピーク 0.748 = **-2.5dBFS**
  （他の録音は swing -4.7 / chime -4.4 / walk -6.8 / rain -11.0）。
  ファイル peak -1.4dBFS + ゲイン -4 = -5.4dBFS に、床（peak -2.9 - 8 = -10.9）と
  足音（-1.4 - 7 = -8.4）が重なると線形和 0.54 + 0.29 + 0.38 = 1.2 > 1.0 になり得る。
  今回の 4 発では起きていない。
- 直し方: 起きてから直しても遅くない。予防するなら `SummerMain.cs` 961 行
  `MakeSfx("sfx_firework", -4f)` → `-6f`（50ms 最大 -13.6dBFS、床から +11.7dB で
  まだ一番大きい）。

### ③ ループ先頭のフィルタ立ち上がり
- 証拠: `wind_bed()` は `prev = 0.0` から始まる 1 次ローパス（時定数 200 サンプル ≈ 9ms）、
  `rain()` の `lp`/`hp_prev` も 0 から。先頭 100ms の DC が morning -0.011 / evening -0.023
  （末尾は +0.0004〜+0.0009）。どれも -33dBFS 以下で、継ぎ目のサンプル跳びは
  隣接差 RMS の 0.11〜0.27 倍。
- 影響: 可聴ではない。中①の修正で連続音の谷が消えれば、残るのはこの程度。
- 直し方（任意）: `wind_bed()` と `rain()` のループの前に 500 サンプルほど空回し
